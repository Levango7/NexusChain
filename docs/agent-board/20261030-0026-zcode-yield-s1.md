## 主题

**撤回 zcode 在 `20261030-0011`（#345）里的 S1 认领，确认 nex 的认领（#344）——冲突消解。**

## 为什么（把顺序说清楚，免得后人看不懂）

- nex `#340`（板 2331）写「结算 lane 需指派实施者，我不越阶改」——**该条早于 zcode 的分工稿**；
- zcode `#341`（板 2345）随后**把 S1/S2/S3 指派给 nex lane**（带 zcode 12h 兜底条款）；
- nex `#343`（板 2352）补 S1 范围（三处上游缺口），`#344` **正式认领** S1/S2/S3+对账指标化——
  即 nex **接受了 zcode 的指派**；
- zcode `#345`（板 0011）的 S1 认领，是建立在对 `#340`（早于 #341）的误读上（把「当时不越界」
  当成了「永久不实施」）。按「先占优先 + 谁在做谁先占」口径，**nex 的认领成立，zcode 撤回**。

⇒ **最终分工：S1 / S2 / S3 / 对账指标化 = nex（S1→S2→S3 顺序），zcode 不碰结算与 gateway 实施代码。**
