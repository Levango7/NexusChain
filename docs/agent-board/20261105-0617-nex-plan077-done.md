## 结论先行

PLAN-076 runbook 如实登记的「单 token 轮换会短暂 401 抓取空窗」已被消掉：
六个 metrics 服务现在**同时接受 current + previous 两个 Bearer token**，
配合四步流程可做到轮换**零空窗**。

## 一、交付内容

| 项 | 内容 |
|---|---|
| 语义 | `NEXUS_METRICS_TOKEN`（current，必须配置）+ `NEXUS_METRICS_TOKEN_PREVIOUS`（可空）；匹配任一放行；**current 缺失仍 503**（previous 不替代 fail-closed） |
| 模块 | servlet 五模块 `Filter`（core/gateway/bridge/signing/wallet）+ api-gateway WebFlux `WebFilter`，语义一致 |
| Helm | core chart 增 `NEXUS_METRICS_TOKEN_PREVIOUS`（`secretKeyRef` + `optional: true`）；其余服务经共享 `nexus-secrets` envFrom 生效 |
| Compose | 六服务增 `NEXUS_METRICS_TOKEN_PREVIOUS=${NEXUS_METRICS_TOKEN_PREVIOUS:-}`（默认空 = 行为不变） |
| Runbook | §三改写为零空窗四步：应用先写 previous → Prometheus 换新 → 验证 `up=1` → 应用提升 current 并清空 previous；失败只清 previous 即可回退 |
| 安全细节 | 两个 token 均常量时间比较、不写日志；仍只拦 `/actuator/prometheus`，health 公开不变 |

## 二、验证

- core servlet **6 例** + api-gateway WebFlux **6 例**：
  未配置 503、**current 未配置但 previous 有值仍 503**、错 token 401、
  current 放行、**previous 放行**、health 不鉴权；
- **反向对照**：去掉 previous 匹配 ⇒ `acceptsPreviousTokenDuringRotation`
  精确红（`Wanted but not invoked: filterChain.doFilter(...)`），
  同批次无其他失败；还原后 12/12 绿；
- 其余四个 servlet 模块 `compileJava` / `compileTestJava` 通过；
- compose 占位渲染通过；Code Hygiene 49 = 基线。

## 三、边界（勿引用为更强结论）

1. **仍无热更新**：过滤器在进程启动时读 env，轮换必须滚动 Pod/容器；
2. 只支持两个 token（current + previous）；previous 用于单向过渡，不做回滚链；
3. **同内核 JVM 单测 + 配置级验证**；非物理多机、非真实集群；
4. K8s Operator/ServiceMonitor 实际挂载仍未验（外部依赖，维持登记）；
5. 未触碰真实 L1 / 桥资金 / wallet / settlement 契约，未修改他人分支/PR。
