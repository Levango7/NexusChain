## 主题

交易类型 `0x04–0x08`（TRANSFER_MULTISIG_MULTISIG / TRANSFER_MULTISIG_NORMAL /
TRANSFER_NORMAL_MULTISIG / ASSET_DEFINE / ATOMIC_EXCHANGE）可让区块**凭空增发**：
手续费被计入 coinbase 并由矿工收走，但发送方余额与 nonce 完全不变，且状态根
（只承诺 `pubkeyHash+height`）无法检测。已用 test-only 复现测试证实，见 PR #520。

## 事实（可复现）

复现命令：

```
.\gradlew.bat :nexus-core:nexus-core:test \
  --tests "org.nexus.core.validate.MultiSigAssetAtomicMintReproducerTest" \
  --tests "org.nexus.core.validate.MerkleStateOrderSensitivityTest"
```

实测输出（5 个 type 全部成立，PR #520 中可查）：

```
[REPRODUCED] type 0x04 fee=50000000 senderBalance=100000000000 senderNonce=7 minerBalance=2050000000
... 0x05 / 0x06 / 0x07 / 0x08 同上 ...
[UNCERTAINTY-A] TransactionVerify(0x04).code=0 message=null
```

可触发路径（逐关卡）：

1. 类型门禁放行：`nexus-core/nexus-core/src/main/java/org/nexus/command/TransactionCheck.java:119`
   `if (15 >= type[0] && type[0] >= 0)` —— 0x04–0x08 在门内。
2. 无余额校验：同文件 `:244-283` 的余额分支只覆盖 0x01/0x02/0x03/0x09/0x0a–0x0f；
   0x04–0x08 走到 `:285 return PayloadCheck(...)`。
3. 未知类型返回码默认为 0：`:297-321` 的 switch 无 `default`，落空后返回
   `new APIResult()`；`ResultSupport` 的 `Code` 为 int 且无初值 ⇒ `0`（实测 `code=0`）。
   `nexus-core/nexus-core/src/main/java/org/nexus/core/validate/AccountRule.java:177`
   只把 `5000` 当失败 ⇒ **放行**。
4. 状态应用是 no-op：`AccountRule.java:246` 调
   `PackageMiner.UpdateOtherAccount`（`nexus-core/nexus-core/src/main/java/org/nexus/consensus/pow/PackageMiner.java:304-357`），
   其中没有 0x04–0x08 分支 ⇒ 余额不减、nonce 不写。
5. 手续费照样入 coinbase：`CoinbaseRule.java:68`（`fees += body[i].getFee()`）与
   `:75`（`coinbase.amount == reward + fees`）；出块侧 `Miner.java:145`。
6. 状态根重放同样 no-op：`MerkleRule.java` 的重放 switch 无 0x04–0x08 分支、
   无 `default`；状态根只比 `Block.calculateMerkleState`（`Block.java:128`），
   叶子是 `Account.getId()`（`pubkeyHash + uint32(blockHeight)`），不含余额/nonce。
7. 手续费率无上限：`Transaction.getFee() = gasPrice * GAS_TABLE[type]`，
   `GAS_TABLE[4..8] = 50000`，`gasPrice` 只受最低值约束 ⇒ 增发量由攻击者任意设定。

影响：任何能出块/能进入交易池的节点都可无限增发；由于状态根不承诺余额，
现有 `StateRootMismatchHandler` / 最终性检查点（`checkpointHash = block.getHash()`）
都不会发现。
