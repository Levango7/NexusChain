| # | 事实 | 实测 |

| 1 | 真实 PG 下 `database_pending` **精确** | 往 `finality_vote_outbox` 插 100 行（`INSERT 0 100`）⇒ `database_pending 100.0`；Prometheus 侧 `value=1e+02`。旧实现会低报 64 |

比单测断言更有说服力。

## 二、CI 侧交付：`FinalityRulesCounterUsageTest`

**缺口**：counter 是单调累计值，裸比较（`dropped_total > 0`）在进程重启
（counter 归零）后**永远不触发**。PLAN-073 的
`increase(nexus_finality_outbox_dropped_total[10m]) > 0` 是对的，但没有任何门禁
保证以后的人记得。

新门禁断言：告警组的 expr 里凡引用 `nexus_*_total`，引用点必须位于
`increase(` / `rate(` 内部；违规时报出「哪条告警组 / 哪条告警 / expr 原文」。

**覆盖范围**：三个告警组（`nexuschain.finality` / `nexuschain.block-adoption` /
`nexuschain.block-persistence`），共 **5 处** counter 引用（finality 3 +
block-persistence 2），当前全部正确包裹 ⇒ 门禁绿 = **5/5 覆盖**，不是「扫到 0 处
所以全绿」。不含 jvm 等组：那里的告警引用 `container_cpu_usage_seconds_total`
等非 `nexus_*` 前缀指标，由 kube-prometheus 自身保证，不在本仓契约范围。
**扩组理由**：引用形状是跨组通用的不变量，没有理由按组豁免。

**一次真实返工（如实登记）**：第一版在测试里自扫规则文件，产生三个假阳性——
① `description` 里给人看的指标名被当引用；② 组级 `#` 注释行被当引用；
③ 组级说明块被算进下一条 alert（于是 `FinalityOutboxUnreadable` 名下报出
`vote_rejected_total`）。改为复用 `PrometheusRulesFixture.groupExprLines()`
（与 PLAN-062/063 同一套「只取 expr 字段」提取规则，仅额外保留 alert 名）后干净。
fixture 的能力从「答一个问题」扩到「答两个问题」，其 Javadoc 已同步更新。

## 五、踩到的坑（如实登记，避免下一个人重踩）

**环境坑 3 个**：

| 坑 | 现象 | 处置 |
|---|---|---|
| Windows → WSL 反向网络不通 | `Test-NetConnection 172.17.218.229:5432` 超时 | **不改 WSL 网络栈**（会影响这台机器上其他 distro/会话）⇒ 整个链路放 WSL 内跑，`localhost` 天然可达 |
| `9090-9091` 被占用 | Prometheus `bind: address already in use` | Windows 侧 Docker 容器 `opsmesh-controlplane-1` 占用 ⇒ 监控栈改用 9097 / 9098 / 9099 / 9094 |
| Alertmanager gossip 端口冲突 | `unable to initialize gossip mesh … port 9094: bind: address already in use` | 显式 `--cluster.listen-address=127.0.0.1:9099` |

**自伤 4 个**（都是本机脚本问题，非产品问题）：

| 自伤 | 现象 | 处置 |
|---|---|---|
| WSL 内 `nohup … &` | `wsl -e bash -c` 会话结束即连带清理，日志文件都没落 | 脚本放 `/mnt/c` 持久侧，用 Windows `Start-Process` 托管，日志也写 `/mnt/c` |
| `set -u` 下引用未设变量 | `FINALITY_STORE: unbound variable` 直接退出 | `${VAR:-default}`，脚本内显式 `export` |
| `pgrep -f alertmanager` | 匹配到 java classpath 里含该词的进程 ⇒ 误判「已在运行」 | `pgrep -af <完整二进制路径>` |
| 按端口清杀脚本 | 端口集合误含 19585 ⇒ **误杀一次 nexus-core**（重启后恢复，无数据影响） | 端口集合只含监控端口，**绝不**包含 19585/5432 |

## 六、边界（勿引用为更强结论）

1. **同内核单机**：WSL2 + Windows 侧进程本机互连，**不是物理多机**；
2. **不是真实机房**：自下载社区二进制，不是集群内 kube-prometheus-stack；
   无 ServiceMonitor、无多副本抓取拓扑；
3. **不宣称「告警已在真实集群触发过」**；
4. scrape 15s + 应用采样 30s 的组合与生产可能有差异（数值按本机配置记录）；
5. **未改任何告警阈值**（演练只验链路；若抓到真实缺陷单独回报）；
6. 实验脚本 / 日志 / webhook 落盘全部留在仓库外；
7. 未触碰真实 L1 / 桥资金 / wallet / settlement lane，未修改他人分支/PR。
