## 一、根因复核：两处**独立**竞态（原留言只列了一处）

1. **窗口跨期**：80ms 窗口 + 背靠背两次调用 ⇒ 两次调用可能跨窗口 ⇒ 两次 flush。
2. **Mockito 登记早于 answer 体**（原留言未列）：`verify(timeout(...))` 在 `doAnswer` 体
   执行完之前就登记了 invocation ⇒ `verify` 返回时 `broadcasts` 仍为空 ⇒
   `broadcasts.get(0)` 抛 `ArrayIndexOutOfBoundsException`。
   **本地探针实证**（探针源码与 XML 留在仓库外 `C:\Users\winge\AppData\Local\Temp\opencode\p080\`，未入库）：

   ```
   PROBE_SIZE_AT_VERIFY_RETURN=0
   PROBE_VERIFY_RETURNED_BEFORE_ANSWER_BODY=true
   PROBE_SIZE_AFTER_JOIN=1
   ```

   ⇒ 原日志的 AIOOBE 有确定机制；「窗口跨期」只会得到 `TooManyActualInvocations`，
   两者是不同失败形态。**只放大窗口压不掉 AIOOBE 那一支。**

## 二、改动（`RPCClientBatchingTest.java`，只改测试）

1. 等待改用**在 `doAnswer` 体内计数的 `CountDownLatch`**，`verify(timeout(...))` 换成
   `verify(after(300).times(1))`（等待期后精确断言「恰好一次」）；
2. 窗口语义用例 80ms → 2000ms（与同文件既有 `singleTransactionWaitsForWindow` 取值一致）；
3. 折叠用例的冲刷改由**合批上限（计数）**确定性触发 ⇒ 两次调用必然同批，
   不再依赖「两次调用落在同一 80ms 窗口内」；
4. **折叠覆盖加强**：两次改传**同内容、不同实例**的交易（生产重试/重复投递的真实形状），
   并显式断言「同内容同哈希」。原用例两次传的是**同一实例** ⇒ 任何「按对象身份去重」的
   实现也会蒙混过关，等于没盖住回归。

未做：Gradle `retry`、可注入 Ticker、删断言、`Thread.sleep` 掩盖、CI 配置改动。
