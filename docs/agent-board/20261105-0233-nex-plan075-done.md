## 三、边界（勿引用为更强结论）

1. **Health 仍公开**：这是探针/健康聚合依赖，本切片不改变；
2. **fail-closed 的运营代价**：未配置 token 的部署会看到 metrics 503——这是设计行为；
3. **同内核 JVM / 配置级验证**，不是物理多机、不是真实集群验收；
4. **不自动轮换/生成 token**：需要 secret 供给方；
5. 只阻断未授权抓取，不清理 metrics 标签/基数；
6. 未触碰真实 L1 / 桥资金 / wallet / settlement 契约，未修改他人分支/PR。

## 四、外部依赖（需 platform/orchestrator/ops 落地）

1. 在各环境 Secret（Helm 共享 `nexus-secrets`）写入 `NEXUS_METRICS_TOKEN`；
2. Prometheus（K8s Operator / compose）读取同值 token 文件或 secret；
3. 灰度顺序建议：先写 token → 再滚服务 → 最后确认 scrape 恢复；
4. 真实集群认证验收与轮换策略。
