## 结论先行

`finality_vote_outbox` 从「只有端点、零指标、零告警」变成**可观测且可告警**，
同时修掉了端点自身两个会给出**错误结论**的语义缺陷：

1. 积压数不再被 `LIMIT 64` 低报（JDBC 改 `SELECT count(*)`）；
2. 数据库读不到不再冒充「0 积压」（新增 `databaseReadable`）；
3. 队列满**永久丢票**从「重试失败」里拆出来（`dropped`），可单独告警；
4. 4 条告警 + promtool 演练 + 指标名/标签契约门禁。

## 一、四条缺口（读代码确认）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **积压数最多只报到 64** | `status()` 用 `loadPendingVotes(DB_FETCH_BATCH).size()`，`DB_FETCH_BATCH = 64`，而 `loadPendingVotes` 是 `LIMIT 64` ⇒ 真实积压 500 行时仍报 64 |
| 2 | **DB 读不到被报成 0** | `status()` 的 `catch (RuntimeException)` 让 `dbPending` 保持 0 ⇒ PG 故障时看起来「没有积压」，与真的 0 行无法区分 |
| 3 | **零指标、零告警** | 全仓 grep `finality_outbox` 在 `.java` / 规则 YAML 中 **0 命中**；`FinalityStalled` 的 runbook 还写着「查 `GET /consensus/finality-outbox`」——要人去 curl，而故障窗口恰恰没人盯屏 |
| 4 | **永久丢票混在临时失败里** | `totalFailed` 三处自增：队列满丢票（永久丢失）、内存重试失败、库行重试失败 ⇒ 丢票只写 ERROR 日志 |

## 二、改动

### 2.1 精确计数 + 可读性

- `FinalityStateStore.countPendingVotes()`：JDBC 用 `SELECT count(*)`、内存用
  `size()`，默认实现回退到无上限 `loadPendingVotes`（`-1` = 未知）；
- `FinalityOutboxStatus` 增 `databaseReadable` / `totalDropped`，
  `isDegraded()` 纳入 `!databaseReadable`；快照增加两个键（字段名向后兼容）。

### 2.2 `FinalityOutboxMetrics`（8 个指标名，pending 两条序列）

`MeterBinder` + `@Component`，**30s 采样、抓取零 DB 访问**：

| 指标 | 类型 | 语义 |
|---|---|---|
| `nexus_finality_outbox_enabled` | Gauge | 最终性共识是否装配（1/0；采样前 NaN） |
| `nexus_finality_outbox_pending{origin="local"\|"received"}` | Gauge | 内存待补写队列长度 |
| `nexus_finality_outbox_database_pending` | Gauge | 持久化 outbox **精确**行数（读不到为 NaN） |
| `nexus_finality_outbox_database_readable` | Gauge | 1=可读或未装配；0=读不到；采样前 NaN |
| `nexus_finality_outbox_enqueued_total` | FunctionCounter | 入队总数 |
| `nexus_finality_outbox_flushed_total` | FunctionCounter | 补写成功总数 |
| `nexus_finality_outbox_failed_total` | FunctionCounter | 重试失败总数（**不含**丢票） |
| `nexus_finality_outbox_dropped_total` | FunctionCounter | **队列满丢票总数（永久丢失）** |

**非 pos 模式**：manager 是无条件 `@Component`，coordinator 才带
`@ConditionalOnProperty(nexus.consensus.mode=pos)`。因此以 coordinator 为判据：
不存在时 `enabled=0`、不采样、`readable=1`，避免 PG 故障在没有最终性的部署里
误报 `FinalityOutboxUnreadable`。

## 四、边界（勿引用为更强结论）

1. **同内核单机 + promtool**：指标与告警只在单机 + promtool 上验证，
   **不是物理多机**，不构成集群结论；
2. **未做真实 Prometheus/Alertmanager 演练**：不声称「已在真实集群触发」；
3. 采样周期 30s ⇒ 指标最多滞后 30s（告警 `for` 已覆盖）；
4. `databasePending` 是本节点视角，不代表其它节点；
5. 本切片只让丢票**可见**，**不改重试策略 / 不加 `attempts` 上限 / 不做自动清理**
   （PLAN-072 已登记为独立决策）；
6. 未触碰真实 L1 / 桥资金 / wallet / settlement lane，未修改他人分支/PR。
