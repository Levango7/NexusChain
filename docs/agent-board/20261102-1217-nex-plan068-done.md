### 一条重要的「仍绿」反向结果（A′）

把 `WebSecurityConfig` 的 `excludePathPatterns(...)` 去掉，让拦截器**名义上**覆盖 `/**`
后，抓取**仍为 200**。这不是用例失效，而是再次独立证实 §“不改白名单”的结论：
`HandlerInterceptor` **根本不参与** actuator 的独立 HandlerMapping。因此**想给
`/actuator/*` 加鉴权必须用 `EndpointFilter` / Spring Security / 独立 `management.server.port`**，
改 `WebSecurityConfig` 无效。这一点对后续“要不要给 actuator 加鉴权”的决策很关键，故如实记录。

真正的可达性对照由 **C**（端点不存在）与 **D**（鉴权被绕过）承担：它们分别精确命中了
会让本门禁失效的两种方式。A′ 在配置层做不到“让拦截器拦到 actuator”，故不能作为该对照。

## 边界（勿引用为更强结论）

1. **同内核单机**：WSL2 里的 PostgreSQL 与 Windows 侧的 nexus-core 同属一台物理机，
   **不是物理多机**，不构成分布式/集群结论；
2. **未起真实 Prometheus / Alertmanager**：只证“抓取文本里序列存在且计数正确”，
   **不证**推送/路由/通知链路，也**未在真实集群触发过告警**；
3. **actuator 目前没有鉴权**：无 token 抓取 200 是 Boot 4 actuator 的路由拓扑事实，
   本 PR 只证“抓取可达、标签可见”，**不是“暴露面已加固”**；
4. **未做吞吐/基数基准**：只验标签值可见，不验高基数下抓取开销；`phase × reason`
   共 27 个序列，基数有界，但高基数开销未测；
5. **合成拒绝**：三个 reason 的触发是测试夹具与一条预置脏行，**不代表真实发生过攻击**；
6. **`checkpoint_limit_exceeded` 的触发**用 K=4 上限的真实判定路径，但
   `checkpoint_hash_invalid` 的运行时实证走的是**收敛路径**（库里预置脏行），
   不是 P2P 攻击帧；两条路径的计数语义由 PLAN-067 的单测分别覆盖；
7. 未触碰真实 L1 / 桥资金 / wallet / settlement lane，未修改他人分支/PR。
