### 2.3 B1 四版本预期冲突点（编译时重点观察）

当前主构建内同时存在 Spring Boot **2.1.6 / 2.2.0 / 2.7.18 / 3.2.5** 四个版本。预期可能在以下点报错：

1. **根 ext 变量泄漏**：根 `build.gradle:41` 的 `springBootVersion='2.7.18'` 若被某子模块引用来拉 `spring-boot-starter-*`，会与 gateway/bridge 的 plugin 3.2.5 在依赖解析阶段冲突。观察是否有 `org.springframework.boot:spring-boot-starter-web:2.7.18` 与 `3.2.5` 同 classpath 的告警。
2. **wallet 2.1.6 的 javax.\***：`nexus-exchange-wallet` 用 `spring-boot-starter-web:2.1.6.RELEASE` + 本地 `lib/` 老 jar（含 `spring-context-5.1.2.RELEASE.jar`）。独立 application 时不与 gateway 共 classpath，但 `buildAll` 聚合构建可能触发依赖冲突报告。
3. **consortium 2.2.0 composite**：`includeBuild 'nexus-consortium'` 下 consortium 自带 `spring-boot 2.2.0`，composite 隔离但参与解析。
4. **测试 BOM 冲突**：根 `build.gradle:79` 已移除全局 test deps（注释说明历史会注入 2.7.18 test BOM 到 3.2.5 app），观察是否仍有残留。

**【贴回日志】** 若 2.2 失败，把失败模块名 + 冲突依赖树（`gradlew.bat dependencies --configuration runtimeClasspath` 对失败模块）贴回。

## 第 4 章 三端联调（Docker）

### 4.1 启动

```bash
cd <项目根>
docker-compose -f docker-compose.yml up -d --build
```

- `docker-compose.yml` 含三个服务：`nexus-gateway`(8080)、`nexus-core`(19585)、`nexus-bridge`(8082)，已配 healthcheck 与 depends_on。
- **【贴回日志】** `docker-compose logs` 全量贴回，重点标注启动期异常栈。

### 4.2 健康检查（等待 healthy 后）

```bash
curl -f http://127.0.0.1:8080/actuator/health     # gateway
curl -f http://127.0.0.1:19585/height             # core
curl -f http://127.0.0.1:8082/api/v1/bridge/status # bridge
```

- 三个都应返回 200。**【贴回日志】** 三个响应体。

### 4.3 端口连通性确认

- 报告称 RPC 桥接端口已从 8545 → 19585。确认 gateway/bridge 实际连到 core 的 19585 而非 8545：
  ```bash
  netstat -ano | findstr 19585
  netstat -ano | findstr 8545
  ```
  期望 19585 有监听，8545 无。

### 4.4 生产 compose（可选，含 PG/Redis/监控）

```bash
docker-compose -f docker-compose.prod.yml up -d --build
```

- 额外起 postgres(5432)/redis(6379)/prometheus(9090)/grafana(3000)。
