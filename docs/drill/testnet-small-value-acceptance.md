# 小额真实链验收清单（仅准备，未执行支出）

日期：2026-11-24

## 证据边界

本清单用于把本机 fake-chain / mock connector 已覆盖的业务契约，推进到真实节点、真实交易池、真实手续费与真实 finality 的验收。它不表示已经执行任何交易，也不授权使用 mainnet 资金。

- **testnet 小额**：可验证真实链交互、nonce、手续费估算、广播、确认、重组处理和节点故障恢复；代币通常无真实价值。
- **mainnet 小额**： additionally 验证真实资金划转、真实费用与真实资产对账；即使只花少量资金，也不能证明高并发、DDoS 抵抗、HA、生产容量或法律合规。
- 把 10 元拆成多个 0.01 元可以增加边界样本，但不能替代上述验证维度。最低有效金额还受链上最小单位、最低转账额和手续费约束，不能机械按法币分拆分。
- NEX 的链上最小单位为 `1e-8 NEX`（`1 NEX = 100000000` 最小单位）。金额在请求、日志、证据表中一律使用十进制字符串或整数最小单位，禁止经 JavaScript `Number` 或二进制浮点换算。

## 1. 执行前硬门槛

- [ ] 明确网络、chain ID、RPC 提供方、合约/桥地址和区块浏览器；由两人复核，禁止仅凭 chain 名称猜网络。
- [ ] 先在 testnet 跑通；mainnet 需单独的书面支出授权、金额上限、付款账户和回滚负责人。
- [ ] 使用专用低余额账户；不导出现有生产私钥，不把助记词、私钥、API secret 写入源码、命令历史、工单或聊天。
- [ ] 密钥只从环境变量或 secret service 注入；日志与证据导出执行 secret 扫描。
- [ ] RPC URL 只允许 `https`，域名与证书可验证；禁止把生产签名服务指向未审计 RPC。
- [ ] 设置逐笔金额、单日累计金额、手续费和总交易数硬上限；超过即 fail closed。
- [ ] 记录初始余额、nonce、链高度和预期最小单位金额；估算总支出，包含最坏手续费。
- [ ] 确认报警接收人、停止开关、交易替换/取消策略和异常联系人。
- [ ] 保存当前代码 commit、配置摘要和镜像 digest；不得在验收中途无记录地换版本。

## 2. 最小样本矩阵

金额以最小单位记录；下表的“最小/边界”由当前链与产品限制计算，不预设法币价值。

| 用例 | 金额/操作 | 核心判据 |
|---|---|---|
| T-01 | 最小允许金额，单笔支付 | 返回唯一 payment ID 与真实 tx hash；链上 from/to/value 与审批意图逐字段一致 |
| T-02 | 最小允许金额 + 1 最小单位 | 无浮点舍入；API、数据库、链上、explorer 与对账值完全一致 |
| T-03 | 低于最小允许金额 | 广播前拒绝为 4xx；无私钥签名、无链上交易、无孤立支付记录 |
| T-04 | 同一 `request_id` 重试 10 次 | 只有一笔业务支付和一笔有效链上支出；重试返回同一支付语义 |
| T-05 | 相同金额连续 10 笔、各自独立 request ID | 金额小不等于幂等；10 笔各有独立 tx hash，nonce 不冲突、不重复使用 |
| T-06 | 手续费不足 / 余额不足 | fail closed；错误可诊断但不泄露密钥；不得扣账后无交易 |
| T-07 | RPC 在签名后、广播前断连 | 重启后用 request ID 与链上/nonce 状态对账，不盲目双发 |
| T-08 | 广播后响应丢失 | 按 tx hash 查询；只能确认既有交易，不得生成第二笔支出 |
| T-09 | 交易长时间 pending | 状态、超时和报警正确；替换交易必须沿用同一业务幂等记录并保留 replaced-by 链 |
| T-10 | 确认后发生可控 testnet reorg（若平台支持） | confirmed 回退、finalized 再推进；无重复记账，事件可追踪 |
| T-11 | 退款/冲正（产品支持时） | 新交易与原支付显式关联；不篡改原交易历史；净额与总额对账一致 |
| T-12 | 节点不可用与恢复 | 有界超时、明确降级、恢复后自动续验；不得静默落 mock connector |

## 3. 每笔交易的取证字段

- [ ] UTC 时间、环境、代码 commit、镜像 digest、chain ID、RPC 标识（不含凭据）。
- [ ] request ID、payment ID、业务状态机每次迁移及原因。
- [ ] 签名前意图摘要：from、to、金额最小单位、nonce、fee 上限、chain ID、payload hash。
- [ ] 签名交易 hash、广播 hash、实际区块 tx hash；若替换交易，保留全部关联 hash。
- [ ] block number、block hash、confirmations、finality 依据和时间。
- [ ] gas/fee 的预估、上限与实际值；账户 nonce 与余额前后差。
- [ ] 数据库支付记录、账本流水、资金看板、explorer 页面、通知/ webhook 投递记录。
- [ ] 链浏览器公开链接；不得把私钥、签名原文或可重放凭证放进证据。

## 4. 对账不变量

- [ ] API 金额字符串 = 数据库整数最小单位 = 链上 value = explorer 显示的最小单位等价值。
- [ ] 业务账户余额差 = 成功支出总额 + 实际链上费用 ± 明确登记的退款/冲正。
- [ ] 每个 request ID 至多一个有效支出意图；替换交易不得重复增加支出总额。
- [ ] 不存在“API 成功但链上无交易”或“链上成功但业务长期未知”的未解释记录。
- [ ] mock/fake-chain 配置在真实验收环境中明确关闭；运行时日志与配置快照可证明没有静默回退。
- [ ] 所有临时报警、失败、重试与人工介入均保留时间线，不能只截取最终成功页面。

## 5. 停止条件与收口

任一条件触发即停止后续支出：网络/合约不符、金额或地址不一致、重复扣款、nonce 冲突、无法解释的状态分叉、密钥疑似泄露、实际费用超过批准上限、出现 5xx 或静默 mock 回退。

收口报告必须分别列出：通过项、失败项、未执行项、实际支出、遗留风险与回滚结果。**小额交易成功只关闭其真实资金链证据缺口，不自动关闭生产 HA、容量、DDoS、物理多机、生产迁移或法务事项。**
