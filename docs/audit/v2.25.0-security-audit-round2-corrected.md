## 二、P0 —— 资金安全漏洞（逐条核实）

### P0-1 商户账户可被任意接管（完全无鉴权的管理 API）— ❌ 仍存在

- `WebConfig.java:93`：`/api/v1/merchants/**` 仍被显式排除在 API key 拦截器之外，注释称 "admin-auth in production"——**但 admin 鉴权不存在**。
- `MerchantController.java:49-54`：`POST /{id}/verify` 无鉴权注解，可把任意商户置为 VERIFIED。
- `MerchantController.java:62-69`：`POST /{id}/api-keys` 无鉴权注解，可为任意商户签发新 API key 并**明文返回 secret**。
- **利用链**：无鉴权调用 verify + api-keys → 拿到合法商户凭证 → 通过 ApiKeyInterceptor → 调退款 API 转移资金。
- **修复方案**：MerchantController 全部写操作端点加 admin RBAC 鉴权（@PreAuthorize("hasRole('ADMIN')")），WebConfig 移除 merchants 排除模式或改为 admin 路径。

### P0-2 签名服务"双人审批"不阻断执行 — ❌ 仍存在

- `TxController.java:161-169`：大额签名仅调用 `createApprovalRequest` 记录审批单，**随后立即继续签名并广播**。代码注释自认："简化版：仅记录审批请求，仍继续执行签名……完整阻断版留待 P3"。
- 任何 SIGNER 角色单方可签任意大额转账。
- **修复方案**：改为阻断式审批——创建审批请求后返回"待审批"响应，不执行签名；审批通过后由独立触发完成签名广播。

### P0-3 钱包服务零鉴权 + 审批人身份自报 — ❌ 仍存在

- `nexus-wallet-service/build.gradle`：无 spring-security/JWT 依赖。
- `WalletController.java`：全部 11 个端点无任何鉴权注解。
- `WalletController.java:138-142`：`/withdrawal/approve` 的 `approverId` 是**请求参数**（自报身份）。
- **单人即可伪造双人审批**：用两个不同 approverId 字符串各调一次 approve 即达 `requiredApprovers=2`。
- 白名单端点 `/whitelist/add` 同样无鉴权——攻击者可自行加白提现地址。
- **修复方案**：wallet-service 引入 spring-security + JWT，approverId 从认证上下文获取而非请求参数，白名单管理加 admin 鉴权。

### P0-4 支付确认不校验交易与订单的绑定 — ❌ 仍存在

- `PaymentServiceImpl.java:215`：`confirmPayment(orderId, chainTxHash)` 仅调用 `isChainConfirmed(chainTxHash)`——只查该哈希是否是链上任意一笔已确认交易，**不校验金额、付款人、收款人与订单的对应关系**。
- **后果**：持有 API key 者可用链上任意一笔小额已确认交易"确认"大额订单 → 订单 PAID → 触发商户发货的 webhook。
- **修复方案**：confirmPayment 增加交易-订单绑定校验：从链上查询交易详情，校验金额=订单金额、收款人=商户地址、付款人合理；删除 skip-confirmation fallback。

### P0-5 退款链路 approved 默认 true（fail-open） — ❌ 仍存在（部分已修复）

- ✅ **已修复**：ID 解析失败不再回退 `DEFAULT_ID_FALLBACK = 1L`，改为返回 400。
- ✅ **已修复**：审批人身份从认证上下文获取（`RefundController.java:106-107`），不信任请求体。
- ❌ **仍存在**：`RefundController.java:244-247` `asBoolean` 方法在 value 为 null 时返回 `true`（"默认批准"）——`approved` 字段缺失时自动批准，fail-open。
- **修复方案**：`asBoolean` null 时返回 `false`（fail-closed），要求显式传 `approved: true` 才批准。

### P0-6 桥的暂停/恢复机制可被无权限操纵 — ❌ 仍存在

- `BridgeController.java`：**整个控制器无任何鉴权**（lock/mint/burn/unlock/pause/resume 全裸奔）。
- `BridgeController.java:59-63`：`pause` 端点无鉴权，任何人可把桥置为 PAUSED = 未授权全桥 DoS。
- `BridgeController.java:65-71`：`resume` 端点无鉴权，且第 68 行 `body.get("validatorIds")` 为 null 时有 **NPE 风险**；`meetsThreshold` 只数 ID 个数不验签。
- **修复方案**：BridgeController 全部端点加 admin/vault 鉴权；resume 改为验真实签名；修复 NPE。

### P0-7 最终性投票验签 fail-open — ✅ 已修复

- `SignatureAggregator.java:127-130`：catch 块已改为 `return false`（fail-closed），标注"P0-6 修复"。
- **状态：v2.20.0 已修复，无需再处理。**
