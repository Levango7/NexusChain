# 方案 PLAN-043：冷恢复节点的长窗口最终性收敛测量（承接 PLAN-042 §四 登记项）

- **状态**：已交付（2026-10-26）；本机两进程 10 分钟窗口测量
- **性质**：验证切片——**产品代码预期零改动**；若收敛确有缺陷 ⇒ 另开修复切片
- **前置**：PLAN-042（节点全量持久化丢失后 5 分钟窗口：自愈全判据通过，但窗口末点
  A 侧本地最终性进度 50% / D 侧 100%，checkpoint hash 一致）——"是暂态还是持续"
  在当时窗口内无法判定，本切片把窗口拉到 10 分钟量级给结论
- **对应 roadmap**：#27「数据库整体不可用…」相关观测项、#30 恢复质量的下游指标

---

## 一、问题（可判定的假设）

PLAN-042 的观测：epoch 422-426 时 A 侧 `FinalityCoordinator` 日志
`finalized=false, progress=50%`，而同一 checkpoint hash 在 D 侧 `finalized=true,
progress=100%`。两种解释：

- **H1（暂态）**：A 的对端票（D 刚冷恢复后重新广播的）在聚合路径上有时延，
  长窗口内 A 也会到 100%——**不是缺陷**；
- **H2（持续缺陷）**：A 的视图**永远**停在 50%（聚合漏收冷恢复节点的票），
  最终性对外不可达 ⇒ 需修复。

**判定标准（预登记）**：D 恢复后连续 10 分钟测量期结束时若 A 侧从未出现
`progress=100%`，且 A/D 两侧 `finality_votes` 行数差持续 >4（=2 个 epoch 的量），
则接受 H2（开修复切片）；否则接受 H1，归档为"冷恢复收敛暂态 ≤ 窗口观测值"。

## 二、实验设计

沿用 PLAN-042 拓扑（A 常驻 mining + D 全量丢失后同参重启），只把 T0 后的观测窗
从 5 分钟拉到 **10 分钟**，每 30s 采样一次，记录：

- A/D 高度；
- A/D 日志**最新** `Finality vote submitted` 的 `progress`/`finalized`；
- A/D 库 `finality_votes`、`finality_checkpoints` 计数与最大 epoch。

## 三、结果（2026-10-26，10 分钟窗口 / 20×30s）

- **高度**：恢复后逐采样一致（141=141 … 1362=1362），10 分钟内无回退、无 ERROR；
- **checkpoint hash**：每个 epoch 两侧同串（例：epoch 683 两侧都是
  `bf4ef01325da6d11640dff1f6b3f247f8568a88604bb1c01502fa48c6254c8b5`）；
- **提交时快照（`submitVote` 返回的 `isFinalized/progressPercent`）**：
  - A：683 次里 **51 次 100%**（7.5%）、632 次 50%；
  - D：683 次里 **595 次 100%**（87%）、88 次 50%；
  - t+240s 出现一次角色互换（A=100% / D=50%）——两侧**都**能到 100%，
    差异是"对端票到达 vs 自己提交"的**到达顺序**，不是状态分歧；
- **DB 终态**：A **1366 票 / 683 检查点**，D **1345 票 / 662 检查点**，max epoch 都是
  683 ⇒ D 缺的 21 个 epoch 的票/检查点落在恢复边界带内（与 50-epoch 补票回看
  窗口的量级一致；D 侧日志 `Vote-sync request (from epoch 633) served with 102 votes`
  即该回填动作）。

## 四、结论与处置

- **H1 成立（不是持续缺陷）**：预登记判据（A 是否出现 100%）通过——A 出现 51 次；
  且两侧 checkpoint 全一致、高度 10 分钟逐块一致、库终态最大 epoch 相同。
  ⇒ PLAN-042 §四 的登记项改为"**暂态已解释**"：50%/100% 是**提交时快照**随
  对端票到达顺序浮动的表现，与本地视图最终是否收敛无因果关系证据。
- **不是缺陷结论**：A 7.5% vs D 87% 的到达顺序不对称在 2 验证人 + D 冷恢复拓扑下
  稳定存在；"对端票到达后本地最终化视图何时翻 true"在日志里**没有观测点**（只有
  提交时快照），本切片未测得 ⇒ 登记为后续测量项（若要对"公开最终化可见性"下
  结论，需一次带端点/内存视图采样的实验）。
- **登记**：更新 PLAN-042 §四 的观察与 roadmap；不改产品代码。

## 五、边界（勿夸大）

- 本机同内核两进程、2 验证人拓扑；3+ 验证人或跨内核拓扑的收敛另测；
- "进度 100%"指**进程内聚合视图**，不等于对外最终化 RPC 语义（口径同既有
  `FinalityCoordinator` 日志字段）；
- 采样粒度 30s：暂态若发生在两次采样之间，以日志 grep 全窗口兜底判据为准。
